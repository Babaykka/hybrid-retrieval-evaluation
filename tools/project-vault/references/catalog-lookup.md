# Локальный поиск по клиенту

При просьбе найти прошлый заказ по клиенту сначала используй `scripts/catalog.py find`. Каталог по умолчанию расположен в `~/.codex/project-vault/private/`, вне рабочих проектов; он доступен новому чату на этом же ноутбуке без памяти предыдущего чата. `--directory` перед командой задает другое личное место. Не помещай каталог или ключ в проект, GitHub, Telegram и резервный пакет самого навыка.

Помощник требует Python с `cryptography`; найди bundled Python через `load_workspace_dependencies`. Если используемый Python не содержит пакет, используй bundled runtime или установи пакет в пользовательское окружение. Далее `<python>` означает выбранный интерпретатор, `<skill>` — папку установленного навыка.

```sh
<python> <skill>/scripts/catalog.py init
<python> <skill>/scripts/catalog.py put < /private/work/record.json
<python> <skill>/scripts/catalog.py find < /private/work/query.json
```

JSON для `put` содержит ровно `aliases` (список приватных вариантов поиска), `id` (нейтральный ID), `repo` (HTTPS-ссылка GitHub), `telegram_url` (HTTPS-ссылка основного поста) и `status` (фактически достигнутая стадия). Неизвестные пока ссылки могут быть пустыми строками. Повторный `put` заменяет запись с тем же `id`. JSON для `find`: `{"query":"PRIVATE_SEARCH_ALIAS"}`; поиск учитывает регистр/пробелы и возвращает все совпадения по alias либо точному ID. Не выбирай один заказ молча при нескольких совпадениях.

Передавай JSON через stdin: программно из памяти или из внутреннего файла с правами `0600` вне проекта. Не используй клиентские имена в аргументах CLI, публичных логах или именах временных файлов. `init` и `put` печатают только статус, количество и нейтральный ID. `find` намеренно возвращает приватную запись для запрошенного поиска; не копируй этот вывод в публичный отчет. Помощник ничего не отправляет по сети и не меняет системную связку ключей.

`catalog.enc` зашифрован AES-256-GCM со случайным 12-байтным nonce и аутентифицированной версией формата. `catalog.key` содержит случайный 32-байтный ключ. Оба файла имеют права `0600`, личная папка — `0700`; ссылки на файлы и hardlink отвергаются. Ключ и шифротекст лежат на том же ноутбуке, поэтому это защита каталога от случайной публикации, а не защита от доступа к учетной записи/устройству.

**Локальный каталог не является удаленной резервной копией.** Для нового ноутбука отдельно сохрани `catalog.key` и `catalog.enc` в выбранном пользователем приватном резервном месте. Не отправляй их автоматически. При восстановлении верни оба файла с правами `0600` в личную папку с правами `0700`, затем выполни `init` и проверочный `find`. Потерянный ключ восстановить из шифротекста невозможно; поврежденный каталог или неверный ключ не перезаписываются автоматически.
