# Подготовка публичного проекта

## Установить состав

Внутренний отчет хранится вне публикуемых каталогов с ограниченными правами. Команда не меняет источник:

```sh
python3 /path/to/project-vault/scripts/inventory.py scan /path/to/project \
  --state /private/work/inventory.sqlite --report /private/work/inventory.json
```

`scan` читает скрытые файлы; не следует по символическим ссылкам, не читает FIFO/устройства и хеширует регулярные файлы SHA-256. Успешные хеши сохраняются после каждого файла. Повторный запуск использует хеш только при совпадении inode/device/size/mtime/ctime/mode; прерванный большой файл читается заново. Это возобновление по файлам, не сохранение промежуточного состояния SHA-256.

Отчет содержит абсолютный путь источника и потенциально приватные имена. Не публикуй его или SQLite. Состояние и отчет запрещено писать внутрь сканируемого корня. Не считай последовательный scan атомарным снимком: останови приложения, меняющие проект, и повторно сверь финальные файлы перед загрузкой.

Архивы ZIP (включая OOXML) и TAR перечисляются без извлечения. На верхнем уровне формат определяется по расширению и распространенным сигнатурам, внутри архива — только по имени; это не исчерпывающий детектор. Ограничения количества записей/ZIP-метаданных явно отражаются в отчете; вложенные архивы, шифрованные записи и неизвестные форматы остаются непроверенными. Помощник не анализирует текст, изображения или метаданные документов. Любой такой контейнер требует отдельного раскрытия и проверки на каждом уровне; при необходимости используй подходящий архиватор с безопасным путем извлечения и лимитами ресурсов. Не запускай содержимое и не извлекай пути `..`, абсолютные пути или ссылки за пределы контролируемого места.

Таблица соответствия должна учитывать каждый исходный объект: включен без изменения, преобразован с новым путем/хешем, дубликат с указателем на сохраненную копию либо исключен с конкретной причиной. Внутреннее число и объем исходников должны сходиться с этим распределением. Комплектность «всего проекта» можно заявить только в смысле этого явно описанного состава. Размер не является основанием для молчаливого исключения наборов данных и производных результатов. Исходный публичный корпус можно заменить upstream-ссылкой, версией и воспроизводимым загрузчиком только при отдельном согласовании пользователя; эмбеддинги, модели и вычисленные результаты от этого не исчезают из состава.

## Обезличить и подтвердить права

Проверяй названия и содержимое файлов, титулы и авторские блоки, адреса/телефоны/почту, ссылки с именами, подписи рисунков, скриншоты и фотографии, лица и идентификаторы, OCR, PDF-метаданные, Office author/last-editor/custom properties, comments, revisions, скрытые листы/слайды, speaker notes, встроенные объекты и миниатюры. После последнего сохранения в нативном приложении повтори проверку и пересобери пакет.

Проверь `.env`, ключи, токены, credentials/config, секреты в коде и ноутбуках, выводы ячеек, логи, базы, URL с авторизацией и git remote. Не печатай найденные секреты в чат/отчет; используй тип и местоположение. Утекший секрет требует удаления из публикуемой версии и отдельного отзыва/замены при наличии полномочий. Секреты не должны попадать даже в зашифрованный публичный архив по умолчанию.

Сохраняй обязательные copyright/license notices и библиографию. Имя стороннего научного автора не равно клиентскому идентификатору. Если нельзя определить право на распространение данных/изображения/стороннего кода, оставь конкретный файл непубличным до выяснения, а публикацию остального продолжай, если она самодостаточна. Не обозначай такую версию как полный оригинал.

Научные графики и технические изображения сохраняй, если они не идентифицируют клиента; пользователь запретил клиентские фото и персональные данные, а не все изображения. Пересчитай результаты после содержательных преобразований. Исполнимые файлы и документы из недоверенного источника проверяй без автоматического исполнения.

## Публичный manifest

После проверки финальных файлов отдельно просканируй именно обезличенный комплект. Для экономии места это может быть ограниченная часть/готовый поток, но источник каждого публикуемого байта должен быть однозначен. Подготовь внутренний JSON review по `inventory_id` из отчета:

```json
{
  "inventory_id": "ID из внутреннего отчета",
  "project_id": "research-case-001",
  "public_paths_reviewed": true,
  "content_and_metadata_reviewed": true,
  "secrets_reviewed": true,
  "rights_reviewed": true,
  "entries": {
    "README.md": {"decision": "include"},
    "data.zip": {"decision": "include", "archive_reviewed": true},
    ".git/config": {"decision": "exclude", "reason": "Old git history"}
  },
  "public_exclusions": ["Старая служебная история Git"]
}
```

Решение требуется для каждого объекта, кроме обычных каталогов. Ссылку/специальный файл нельзя включить этим помощником. Архив допускается только с явным `archive_reviewed: true` после фактической внешней проверки, включая вложения. Эти флаги фиксируют вывод проверки, а не заменяют ее. Review содержит исходные пути и остается внутренним.

```sh
python3 /path/to/project-vault/scripts/inventory.py public-manifest \
  --state /private/work/clean-inventory.sqlite \
  --review /private/work/review.json --output /public/release/MANIFEST.json
```

Экспорт выводит только проверенные относительные пути включенных файлов, размеры, SHA-256, нейтральный ID и согласованные публичные причины исключений. Перед экспортом он заново перечисляет дерево без следования по ссылкам и блокирует добавленные, удаленные или изменившиеся объекты; это не атомарная блокировка дальнейших изменений. Он не переименовывает файлы, не очищает их и не доказывает обезличивание; проверь полученный manifest перед публикацией. Не допускай имя клиента даже в пути исключенного файла публичного manifest. Это manifest файлов: пустые каталоги и специальные объекты учти отдельно в схеме упаковки/восстановления, если они нужны. Manifest частей транспорта и manifest восстановленного дерева — разные объекты; сохрани оба, если применена упаковка.

Для канала подготовь краткий человеческий пост: задача; что сделано; подтвержденный результат; состав; версия; ссылки; инструкция восстановления. Не подменяй достоверное авторство присвоением чужого текста/исследования: описывай фактический вклад пользователя. Не добавляй сведения об аккаунте/устройстве как автора.
