# Project Vault

Сохрани воспроизводимую работу и понятный публичный кейс. Не связывай успех с памятью чата: результат должен находиться по каталогу и восстанавливаться по сохраненным инструкциям.

## Постоянные настройки

- Публичный GitHub — основное место для всей обезличенной разработки и результатов. Большие файлы размещай в подходящем хранилище GitHub, например Releases с частями, а не заменяй их одними ссылками на Telegram.
- Публичный канал `https://t.me/zzakazzy` содержит зеркало полного разрешенного обезличенного проекта, описание, ссылки на части, GitHub и каталог работ.
- В публичных материалах и любых репозиториях, включая private, не должно быть персональных имен, фотографий и других идентификаторов клиента. Связь «клиент → нейтральный ID» допускается только в отдельном зашифрованном личном каталоге вне GitHub и Telegram, если пользователь хочет такой поиск. Не сохраняй имена в этом навыке.
- Публикация оригинала с персональными данными не следует из согласия сохранить весь проект. Обезличивание меняет копию для публикации, исходники остаются до подтвержденного восстановления. Не исключай данные, исходники, результаты и промежуточные материалы только из-за размера. Замена исходного общедоступного корпуса ссылкой и загрузчиком требует явного согласования; она не распространяется на производные результаты.
- Согласованная текущая публикация не дает бессрочного разрешения на новые публикации, сообщения или удаления. Используй уже данную авторизацию для того же действия; при новой задаче установи ее фактический объем. Не вводи повторное согласование, если оно уже есть.

## Закрыть и опубликовать заказ

Прочитай [references/publication.md](references/publication.md). Начни с фактических файлов, git-состояния, свободного места и доступного транспорта, а не с предположения об исходниках или правах. Дай проекту нейтральный ID.

1. Составь внутреннюю инвентаризацию всего корня, включая скрытые файлы, ссылки и архивы. Используй `scripts/inventory.py scan`; храни state и отчет вне исходников и публикации. Помощник ничего не обезличивает и не удаляет. Его список архивов не доказывает проверку содержания.
2. Подготовь обезличенные материалы и явную таблицу «исходный объект → опубликованный объект / преобразование / исключение с причиной» во внутреннем рабочем месте. Если что-то нельзя законно опубликовать, останови публикацию затронутых файлов, сохрани их локально и покажи пробел; не объявляй остальное полным оригиналом.
3. Проверь содержание, визуалы, имена путей, метаданные и секреты. Сохрани научную библиографию, законные ссылки на источники и обязательную стороннюю атрибуцию. Если требования к удалению имен конфликтуют с обязательной атрибуцией, не удаляй ее молча: исключи затронутый материал из публикации до решения.
4. Сформируй окончательный состав и публичный manifest по фактическим финальным байтам. Сделай новую чистую git-историю; не публикуй старые `.git`, reflog, удаленные ветки, рабочие отчеты или каталог клиента. Пиши описание только на основании проверенной работы и результатов.
5. Загрузку, чтение обратно, восстановление и фиксацию ссылок выполняй по [references/restore-and-cleanup.md](references/restore-and-cleanup.md). Пока проверка не закончена, статус — «загружено, восстановление не проверено», а не «архив готов».

При малом свободном месте не создавай вторую полную копию. Преобразуй небольшие файлы по одному; для больших неизменяемых данных используй поток и ограниченные части с контролем свободного места. Если транспорт или обезличивание требует полного временного файла, а места нет, используй разрешенное дополнительное хранилище или останови эту стадию. Не удаляй непроверенные исходники ради продолжения.

## Найти и восстановить

Для поиска по клиенту прочитай [references/catalog-lookup.md](references/catalog-lookup.md) и проверь локальный зашифрованный каталог через `scripts/catalog.py find`; место по умолчанию — `~/.codex/project-vault/private/`. После сохранения ссылок добавь/обнови запись через `put`, если пользователь хочет такой поиск. Имена не попадают в репозитории или канал. Новый чат на этом ноутбуке использует тот же каталог; для нового устройства нужны отдельно сохраненные ключ и шифротекст, автоматической отправки нет.

Либо найди нейтральный ID в GitHub/канале. Скачай manifest и инструкцию, проверь ссылки и все контрольные суммы. Восстанови проект в отдельный путь и запусти значимую проверку согласно инструкции. Если приватное соответствие отсутствует, не обещай поиск по имени клиента; ищи по предмету, дате и известным материалам.

## Вести канал

При закрытии заказа создай один основной пост с нейтральным ID, предметом, вкладом, проверенными результатами, составом, ограничениями, инструкцией восстановления и ссылками на вложения/GitHub. Публикуй части как ответы или связанные сообщения и обновляй основной пост/каталог после проверки ссылок. Исправления отмечай версией и датой; не теряй доступ к ранее выданной версии.

Согласование вести канал распространяется на посты этих проектов и связанные обновления. Не выдумывай выполненные заказы, результаты или метрики; не назначай произвольное расписание и не создавай автоматизацию без запроса пользователя. Не публикуй внутреннюю переписку, цены, клиентские контакты или историю обсуждений.

## Освободить место

Применяй процедуру [references/restore-and-cleanup.md](references/restore-and-cleanup.md). Назови точные пути и объем, проверь существующую авторизацию удаления и соблюди применимые правила безопасного удаления. Загрузка не равна резервной копии; скачивание одной маленькой части не равно восстановлению всего проекта. Никогда не расширяй область удаления до родительской папки или соседних заказов.

## Сохранить сам навык

Навык расположен на уровне пользователя, вне проекта. В разрешенный резервный пакет включи `SKILL.md`, `agents/openai.yaml`, все три reference, `scripts/inventory.py` и `scripts/catalog.py`; приложи команду проверки и инструкцию установки в `$CODEX_HOME/skills/project-vault` или `~/.codex/skills/project-vault`. Перед публикацией пакета проверь его отдельно. Не включай внутренний state, реальные клиентские соответствия и учетные данные. Секреты и ключ расшифрования сохраняются отдельно доступным пользователю способом.
